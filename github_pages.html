누구나 따라 하는 GitHub 배포 가이드

내가 만든 프로그램,
깃허브에 올려서 누구나 쓰게 만들기

GitHub 회원가입부터 저장소 만들기, 파일 업로드, GitHub Pages 배포, 그리고 다른 사람이 인터넷 주소만으로 내 프로그램에 접속하게 만드는 전 과정을 순서대로 설명합니다. 코딩 도구를 따로 설치하지 않고, 웹 브라우저만으로 끝까지 따라 할 수 있도록 구성했습니다.

전체 흐름: 파일 준비 → 저장소 업로드 → Pages 배포 → 전 세계 누구나 웹 주소로 접속

1
준비 단계

GitHub 계정 만들기

GitHub는 프로그램 파일을 저장하고, 다른 사람과 공유하고, 무료로 웹사이트처럼 공개할 수 있는 사이트입니다. 가장 먼저 계정을 만듭니다.

  1. https://github.com 주소로 접속합니다.
  2. 오른쪽 위(또는 첫 화면 중앙)에 있는 Sign up 버튼을 클릭합니다.
  3. 이메일 주소를 입력합니다. 평소 자주 확인하는 이메일을 사용하세요(인증 메일이 옵니다).
  4. 비밀번호를 입력합니다. 영문 대소문자, 숫자, 특수문자를 섞어서 15자 이상 또는 8자 이상 조건에 맞게 만듭니다.
  5. 사용자 이름(Username)을 정합니다. 이 이름은 나중에 내 웹사이트 주소(username.github.io)에 그대로 들어가므로, 영문과 숫자로 신중하게 정하는 것을 추천합니다.
  6. 화면에 나오는 간단한 퍼즐(사람인지 확인하는 절차)을 완료합니다.
  7. 가입할 때 입력한 이메일 받은편지함을 열어, GitHub에서 보낸 인증 코드를 확인하고 입력합니다.
  8. 이후 나오는 설문(어떤 용도로 쓸지 등)은 건너뛰기(Skip)해도 무방합니다.
💡 TIP

사용자 이름은 나중에 바꿀 수도 있지만, 바꾸면 기존에 만든 웹사이트 주소도 함께 바뀝니다. 학생이나 동료에게 공유할 계획이라면 처음부터 신중하게 정해두는 것이 좋습니다.

2
저장 공간 만들기

새 저장소(Repository) 만들기

저장소(Repository, 줄여서 레포)는 내 프로그램 파일들이 들어갈 폴더라고 생각하면 됩니다.

  1. 로그인한 상태에서 GitHub 오른쪽 위 + 아이콘을 클릭한 뒤 New repository를 선택합니다.
  2. Repository name(저장소 이름)을 입력합니다. 이름 규칙에 따라 사이트 주소 형태가 달라집니다(아래 표 참고).
  3. Public을 선택합니다. GitHub Pages로 무료 배포하려면 저장소가 공개(Public) 상태여야 합니다.
  4. Add a README file 체크박스는 선택해도 되고 안 해도 됩니다(선택하면 저장소 설명 파일이 자동 생성됩니다).
  5. Create repository 버튼을 클릭합니다.

저장소 이름에 따른 웹사이트 주소 차이

저장소 이름결과 웹사이트 주소용도
사용자이름.github.io
(예: ygmaster2.github.io)		 https://사용자이름.github.io/ 나만의 대표 홈페이지 하나를 만들 때
그 외 아무 이름
(예: bongtu)		 https://사용자이름.github.io/저장소이름/ 여러 개의 프로그램을 각각 따로 만들 때
💡 TIP

예시로 주신 ygmaster2.github.io/bongtu 주소는 사용자 이름이 ygmaster2이고, bongtu라는 이름의 저장소를 따로 만들어 그 안에 프로그램을 넣은 경우입니다. 여러 개의 미니 프로그램을 만들 계획이라면 이렇게 프로그램마다 저장소를 따로 만드는 방식을 추천합니다.

3
콘텐츠 준비

배포할 프로그램 파일 준비하기

GitHub Pages는 정적 웹페이지(HTML, CSS, JavaScript로 만든 페이지)를 인터넷에 공개해주는 서비스입니다. 가장 중요한 규칙은 딱 하나입니다.

⚠️ 반드시 지켜야 할 규칙

사이트의 시작 화면이 되는 파일 이름은 반드시 index.html 이어야 합니다. 대문자를 섞거나 다른 이름(예: main.html)으로 하면 첫 화면이 열리지 않습니다.

내 컴퓨터에 다음과 같은 폴더 구조로 파일을 준비합니다. 폴더 이름은 자유롭게 정해도 됩니다.

my-program/
├── index.html      (필수, 시작 화면)
├── style.css       (선택, 디자인 파일)
├── script.js       (선택, 동작을 담당하는 파일)
└── images/         (선택, 이미지가 있다면 이 폴더에 모아둡니다)
    └── logo.png

아직 프로그램이 없다면, 아래 예시 코드를 메모장(또는 코드 편집기)에 붙여넣고 index.html이라는 이름으로 저장해 연습해볼 수 있습니다.

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <title>나의 첫 배포 페이지</title>
</head>
<body>
  <h1>안녕하세요! 저는 GitHub Pages로 배포했어요 🎉</h1>
  <p>이 페이지는 누구나 인터넷 주소로 접속할 수 있습니다.</p>
</body>
</html>
💡 TIP

파일을 저장할 때 인코딩(문자 형식)을 UTF-8로 저장해야 한글이 깨지지 않습니다. 메모장 기준 "다른 이름으로 저장" 창 하단의 인코딩 항목에서 UTF-8을 선택하세요.

4
업로드

파일을 GitHub 저장소에 업로드하기

별도 프로그램 설치 없이, 웹 브라우저 화면에서 마우스로 끌어다 놓는 것만으로 업로드할 수 있습니다.

  1. 2단계에서 만든 저장소 페이지로 이동합니다.
  2. Add file 버튼(또는 Code 탭 안의 파일 목록 위쪽)을 클릭하고 Upload files를 선택합니다.
  3. 내 컴퓨터의 my-program 폴더 안에 있는 파일들(index.html 등)을 화면 가운데 점선 상자 안으로 마우스로 끌어다 놓습니다. 또는 choose your files 글자를 클릭해 파일 선택 창에서 고릅니다.
  4. 주의: 폴더째로 끌어다 놓으면 브라우저에 따라 폴더 구조가 그대로 유지되지 않는 경우가 있습니다. index.html이 저장소의 가장 바깥(루트)에 위치하도록 업로드합니다.
  5. 화면 아래로 내려가면 Commit changes 입력창이 있습니다. "파일 업로드" 같은 간단한 설명을 남겨도 되고, 기본값 그대로 두어도 됩니다.
  6. Commit changes(초록색) 버튼을 클릭하면 업로드가 완료됩니다.
💡 TIP

업로드가 끝나면 저장소 파일 목록에서 방금 올린 파일들이 보이는지 꼭 확인하세요. index.html이 폴더 안이 아니라 목록 맨 위(루트)에 바로 보여야 정상입니다.

가장 중요한 단계

GitHub Pages 켜서 배포하기

파일을 올려두는 것만으로는 아직 웹사이트가 되지 않습니다. GitHub Pages 기능을 "켜는" 설정이 필요합니다.

  1. 저장소 화면 위쪽 메뉴에서 Settings 탭을 클릭합니다.
  2. 왼쪽 사이드바를 아래로 내려 Code and automation 항목 안에 있는 Pages를 클릭합니다.
  3. Build and deployment 항목에서 Source가 Deploy from a branch로 되어 있는지 확인합니다.
  4. 바로 아래 Branch 드롭다운에서 main을 선택하고, 옆의 폴더 선택은 / (root)를 선택합니다.
  5. Save 버튼을 클릭합니다.
  6. 화면 상단에 초록색으로 배포가 진행 중이라는 안내가 뜹니다. 보통 1~3분 정도 기다리면 완료됩니다.
  7. 페이지를 새로고침하면 같은 위치에 "Your site is live at https://사용자이름.github.io/저장소이름/" 문구와 함께 Visit site 버튼이 나타납니다.
💡 TIP

처음 켤 때는 시간이 조금 더 걸릴 수 있습니다. 5분이 지나도 주소가 뜨지 않으면 Settings → Pages 화면을 새로고침해 보세요.

6
결과 확인

배포된 주소로 접속해 확인하기

  1. Settings → Pages 화면에 있는 Visit site 버튼을 클릭하거나, 주소창에 https://사용자이름.github.io/저장소이름/를 직접 입력합니다.
  2. 내가 만든 index.html 화면이 그대로 보이면 성공입니다.
  3. 이 주소를 다른 사람에게 카카오톡, 문자, 이메일 등으로 보내면, 그 사람도 별도 설치 없이 브라우저에서 바로 접속해 사용할 수 있습니다.
⚠️ 화면이 안 보이거나 이상하게 보인다면

키보드에서 Ctrl + Shift + R(맥은 Cmd + Shift + R)를 눌러 캐시를 지우고 새로고침해 보세요. 브라우저가 이전 화면을 저장해두어 새 내용이 바로 안 보이는 경우가 많습니다. 그래도 안 되면 8단계 문제 해결을 참고하세요.

7
유지 보수

내용을 수정하고 다시 배포하기

한 번 배포를 설정해두면, 이후에는 파일만 새로 올리면 자동으로 사이트에 반영됩니다. 별도로 Pages 설정을 다시 할 필요가 없습니다.

방법 A. GitHub 화면에서 바로 수정하기 (간단한 수정)

  1. 저장소에서 수정할 파일(예: index.html)을 클릭합니다.
  2. 오른쪽 위 연필 모양 Edit 아이콘을 클릭합니다.
  3. 내용을 수정한 뒤, 화면 아래 Commit changes를 클릭합니다.
  4. 1~2분 뒤 사이트 주소를 새로고침하면 바뀐 내용이 반영되어 있습니다.

방법 B. 파일을 통째로 다시 업로드하기 (큰 수정)

  1. 저장소의 Add file → Upload files로 이동합니다.
  2. 수정한 파일을 다시 끌어다 놓습니다. 같은 이름의 파일은 자동으로 덮어써집니다.
  3. Commit changes를 클릭합니다.

자주 발생하는 문제와 해결법

증상원인 / 해결 방법
사이트 주소로 들어가면 404 Page not found index.html 파일이 저장소 맨 바깥(루트)에 없거나, 파일명 철자가 다른 경우입니다. 파일 목록에서 이름과 위치를 다시 확인하세요.
화면은 뜨는데 디자인(CSS)이 안 먹음 index.html 안에서 CSS 파일을 연결한 경로와 실제 업로드된 파일 이름의 대소문자가 다른 경우가 많습니다. GitHub Pages는 대소문자를 구분합니다.
이미지가 안 보임 이미지 경로가 내 컴퓨터 기준 경로(예: C:\images\...)로 되어 있지 않은지 확인하고, images/logo.png처럼 저장소 안의 상대 경로로 수정합니다.
한글이 깨져서 보임 파일을 저장할 때 인코딩이 UTF-8이 아니었을 가능성이 큽니다. 다시 UTF-8로 저장 후 재업로드합니다.
Settings에 Pages 메뉴 자체가 없음 저장소가 Private(비공개)로 되어 있을 수 있습니다. Settings 맨 아래 Danger Zone에서 Public으로 바꾸거나, 저장소를 새로 Public으로 만듭니다.
분명 수정했는데 사이트에 그대로 반영 안 됨 배포에는 보통 1~3분 정도 시간이 걸립니다. 잠시 기다린 뒤 캐시를 지우고(Ctrl+Shift+R) 새로고침하세요.

실제 화면 캡처를 참고할 수 있는 사이트

GitHub 화면은 종종 업데이트되기 때문에, 이 매뉴얼에는 실제 화면 캡처 대신 흐름을 설명하는 도식을 넣었습니다. 매뉴얼에 최신 실제 화면 스크린샷을 함께 넣고 싶다면 아래 공식 사이트의 이미지를 참고해서, 자신이 직접 그 단계를 진행하며 화면을 캡처하는 것을 추천합니다(직접 캡처한 화면이 가장 정확합니다).

🔗 참고 사이트 목록
  • GitHub Pages 공식 문서 — docs.github.com/en/pages (배포 방법의 최신 공식 설명과 화면 캡처 포함)
  • GitHub Pages 빠른 시작 가이드 — docs.github.com/en/pages/quickstart (첫 배포를 순서대로 캡처와 함께 안내)
  • 저장소 만들기 공식 문서 — docs.github.com 에서 "Creating a new repository" 검색
  • GitHub Skills (실습형 강좌) — skills.github.com (직접 따라 하며 실제 화면을 그대로 보는 대화형 튜토리얼, "GitHub Pages" 코스 제공)
💡 화면 캡처하는 방법

Windows는 Win + Shift + S, Mac은 Cmd + Shift + 4를 누르면 원하는 부분만 캡처할 수 있습니다. 캡처한 이미지를 매뉴얼 각 단계 아래에 붙여 넣으면 훨씬 이해하기 쉬운 자료가 됩니다.

마무리 체크리스트

  • GitHub 계정을 만들고 이메일 인증까지 완료했다
  • Public으로 저장소를 새로 만들었다
  • index.html 파일이 저장소 맨 바깥(루트)에 있다
  • Settings → Pages에서 Branch를 main, 폴더를 / (root)로 설정하고 저장했다
  • "Your site is live at ..." 메시지를 확인했다
  • 실제 주소로 접속해 화면이 정상적으로 보이는 것을 확인했다
  • 주소를 다른 사람에게 보내 접속이 되는지 함께 확인했다
이 매뉴얼은 GitHub Pages를 이용해 정적 웹페이지(HTML/CSS/JS)를 배포하는 절차를 설명합니다. Node.js 빌드가 필요한 프로그램(React 등)은 별도의 빌드 및 배포 설정이 추가로 필요할 수 있습니다.
